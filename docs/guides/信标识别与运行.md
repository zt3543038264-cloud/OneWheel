# 旧 Qcar 信标识别与当前菜单接入

2026-11-09，基于当前 `76c961e` 的 Roll 增量 PI 版本恢复。恢复来源是删去旧模块前的 `7a053b2a966b72461266abb3c2b32254fadcb053`（`3a0e79c^1`）。没有用旧控制器覆盖当前直立、IMU、电机驱动、方向、网络或 Roll 默认参数。

2026-11-12追加动态中线、近处转弯、丢标搜索和重捕获；实现差异、参数及本次验收见[信标连续追踪移植](../design/信标连续追踪移植.md)。

## 恢复范围与数据流

`code/Estimation/Beacon/` 恢复旧项目的图像处理、连通域、目标筛选/时序追踪、三信标路径排列、像素转世界坐标，以及原有形态学、Tophat、Sobel、Otsu、MLP、OCSVM 辅助源码。原始 27 个文件逐字节另存在 `docs/reference/qcar-beacon/`，扩展名 `.in`，`manifest.json` 记录来源和 SHA256，不参与编译。

运行链路：

```text
MT9V03X 新帧 → CPU1 稳定灰度副本
→ 固定阈值二值化 → 可调邻域连通域 → 目标过滤/追踪
→ 按距离取最多 3 个候选 → 枚举访问顺序 → 选第一个目标
→ CPU1 结果信箱 → CPU0 当前 Run 的转向/速度目标
→ 当前三轴平衡与混控 → 当前电机驱动
```

MLP、OCSVM、Tophat、Sobel 等辅助源码可供后续调试；旧项目这三条实际识别路径没有调用它们，本轮也没有擅自全部串到识别链中。原有循迹元素模块和 Path 示教导航继续保留。信标路径排列是**当前画面中最多三个目标的局部访问排序**，不等同于全场建图或全局路线规划；现有 Path 仍是另一套功能。

| Beacon Mode | 实际路径 |
|---|---|
| 0 | 原有赛道循迹，信标关闭；默认值 |
| 1 | Distance：固定阈值、几何/灰度过滤、距离排序、路径代价选择 |
| 2 | Time：在候选筛选中加入历史目标追踪和灰度变化判断 |
| 3 | Time Pro：使用旧增强时序分类器，再进行距离排序和路径代价选择 |

时序窗口仍是 40 帧，实际时间取决于摄像头帧率。由任一信标模式切换到另一模式或切回循迹，会清除旧识别历史，输出携带模式编号，CPU0 不接纳与当前模式不一致的有效目标。无新图像不会伪造新帧。

## 菜单操作

1. 保持 `STOP`，进入 **Params → Beacon**。
2. 将 **Mode 0..3** 先设为 **1**；选 **Camera On**，请求 CPU1 启动摄像头。此操作不启动电机。
3. 返回主菜单 **Image** 查看灰度或二值图。2026-11-10 已修复信标标记的绘制行范围，BIN+L会叠加选中目标的中心短线；数量、坐标和有效性也可在Beacon页底部查看。相机启动、原始图像诊断及新增读数见 [摄像头黑屏诊断](摄像头黑屏诊断.md)。
4. 回 **Beacon**，观察底部 `N/总候选、NEXT、X/Y、MID、ERR、TURN、MISS` 和 `TRACK/NEAR/SEARCH/HOLD`，调识别与追踪参数。X/Y为当前有效目标的原图像素，MID为动态追踪列；搜索时不会显示伪造的目标坐标。参数只能停车修改；**Save** 只保存本页参数，不改写已保存的 Roll、Motor 等页。
5. 准备运行时，在 **Beacon → Run Beacon** 按当前 Run 的双次确认流程操作（3 秒内再次确认）。需摄像头 READY、图像新鲜、目标有效、模式匹配，并通过现有平衡启动检查。
6. Run正在运行时，在Run动作行确认一次结束追踪并退回Balance，再确认一次完全停机。返回键只退菜单，不等于停止。
7. 改回 **Mode=0** 恢复原有循迹。循迹的 IPM 标定只允许在 Mode=0 下执行。

Beacon 模式下，主菜单 Run 也使用当前选定的信标视觉来源；Balance、单轴测试及 Path 不因选择 Beacon 而变成信标运行。菜单没有恢复旧 Mode2～10 编号。

## 参数说明

| 菜单项 | 默认值 | 意义 |
|---|---:|---|
| Mode 0..3 | 0 | 选择上述识别路径 |
| Threshold | 60 | 灰度大于等于阈值记为白色；增大通常减少亮区域 |
| Radius | 3 px | 合并相邻白色像素的邻域半径，1～4；过大会粘连多个目标 |
| Min Gray | 100 | 时序分类器的亮度门槛 |
| Max Miss | 5 帧 | 历史追踪允许的连续失配帧数；不代表允许沿旧目标继续前进 |
| Min Std | 20 | 灰度标准差门槛；Time 路径另保留旧大目标阈值 40 |
| Min Ratio | 1 | Distance 的外接框宽/高门槛 |
| Near Area | 20 px | Distance 中近处小区域的剔除门槛 |
| Match px | 3 px | 时序追踪的位置匹配阈值；仍同时保留旧算法的框重叠等条件 |
| Speed m/s | 0.15 | 有目标时给当前 Run 的前进速度上限，另受原 Run 和动量权限限制 |
| Yaw Max | 30 °/s | 信标模式下的转向目标角速度上限，另受原有转向限制约束 |
| Mid X | 93 px | 图像期望目标横坐标；对准光轴后再调实际转向 |
| W Distance | 0.5 | 路径归一化距离代价权重 |
| W Turn | 0.5 | 路径归一化转角代价权重 |
| W Continue | 0.2 | 有历史目标时，首目标偏离期望中线的代价权重 |
| Track Row | 50 px | 目标cy低于此行时追固定Mid X，达到后使用动态中线；必须小于Turn Row |
| Turn Row | 110 px | 目标cy达到此行时锁存近处转向，随后丢标可立即进入搜索 |
| Line Kp | 0.8 | 动态中线偏移的行号系数；偏移=Line Kp×cy−Line Offset |
| Line Offset | 41 px | 动态中线偏移常数；左右接近方向使用相反偏移 |
| Search Err | 60 px | 搜索时方向偏差的绝对值，0关闭搜索；不是PWM或角度 |
| Search Frames | 20 | 普通丢标进入搜索前等待的处理帧数；近处转弯锁存后无需等待 |

各模式并非使用所有筛选参数；完整分支在 `image_process.c`、`target_classifier.c`。当前全表102项，含21项Beacon；cfg Schema及上位机源码profile同步，停车修改、分组保存。没有新增信标专用波形包，也没有替换桌面上位机可执行程序。

## 目标丢失与控制边界

- 没有可信目标：本帧`valid=0`，X/Y不沿用旧值。尚未满足搜索条件时速度目标为0；满足搜索条件后，单独发布`searching/steer_valid`和方向偏差，不能把搜索状态当作识别成功。
- 原有失帧、持续丢线、启动渐增、速度斜坡、倾角和电机链路保护继续有效。目标限速归零不等同于物理瞬间停止；原 Run 仍按既有减速/超时逻辑处理。
- 2026-11-12接入monotroch的动态中线、近处转弯与丢标搜索控制。实际搜索必须属于本次Run、已经见过有效目标、视觉帧新鲜且模式匹配；持续丢标600ms或失帧仍退出Run并保持Balance。
- 信标不依赖循迹 IPM；距离与角度仍使用旧 `pixel2world.c` 的相机内外参。**这些参数尚未按当前镜头、安装高度、俯仰角重标定**。循迹 IPM 菜单不能替代它。现有 Lean 压弯仍保留原 IPM 条件，无有效 IPM 时不启用这条压弯分支。
- 本轮验证的是软件接线与算法边界。真实场地曝光、信标灯形态、相机标定、左右转向以及动态处理帧率仍需上板核对，不能仅凭编译通过认定已能跑完整赛道。

## TC264 内存适配与修复

原模块直接复制会超过芯片 SRAM/PSRAM。本版复用现有二值图；连通域使用 5 行滚动标签、16 个前景标签上限；保留最多 3 个路线目标。40 帧追踪窗口中的灰度和标准差量化为 uint8，最多产生不足 1 灰度单位的截断差异；原始源码副本保留全精度实现供对照。

信标工作数据放 CPU1 DSRAM，算法代码放 Flash，视觉调度从 PSRAM 移至 Flash，原逐行图像热点仍在 PSRAM。CPU0 数据组允许按独立段填入既有布局空隙，没有扩大物理内存或缩减既有栈/堆预留。当前空余 RAM 较紧，后续大缓冲必须先检查链接 map。

同时修复标签合并后的灰度平方和/最小灰度、零目标路线索引、分类结果容量、像素坐标边界、追踪初始化、连续丢帧计数以及可选 MLP-max 调用等问题。活动识别路径不分配堆内存。
