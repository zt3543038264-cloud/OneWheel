# 独轮车信标标定指南

调左右绕灯，先用一盏灯定出车身正前方、开始绕灯的位置和希望通过的间距，再用两盏灯验证自动选边。左右共用一组参数。菜单里的行号和偏移量都是像素，车灯间距要在场地上实测。

## 1. 停车开相机，读准一盏灯

1. 保持 `STOP`，固定相机，扶车到正常运行时的俯仰姿态。使用比赛或测试时同型号、同高度的灯，固定地面和光照条件。在地面贴一条沿车身前进方向的中心线。
2. 打开 **Params → Beacon**，记下当前参数。选 **Mode 1 → Camera On**。打开 **Image → BIN+L**，看红色短线是否落在要测的灯上。绿色线是程序当前希望灯中心落到的列。
3. 回到 **Beacon** 页，确认只放一盏灯时显示一个有效候选，状态为 `TRACK` 或 `NEAR`。记录稳定几帧的 `X、Y`。图像为 188 × 120，`X` 向右增大，`Y` 向下增大。跟踪时 `MID` 是瞄准列，`ERR = X − MID`。只在有效检测时采点；`SEARCH` 时的 `ERR` 是搜索指令。

## 2. 三次摆位，定出五个参数

| 摆位 | 现场操作 | 参数 |
|---|---|---|
| 正前方 | 把灯放在车身中心线上，距离稍远，处于 `TRACK`。读稳定的 `X`，再沿中心线换一个远处位置复核。若两处的 `X` 差异明显，先检查相机朝向和安装偏心。 | **Mid X** 取正前方灯的代表列。写入后正对远灯时，`ERR` 应接近 0。 |
| 开始绕灯 | 把灯放在你希望车开始绕行的实际距离，记录灯中心的行号 `Y₁` 及车到灯的距离。希望此时从直追平滑过渡，可取起始横向偏移为 0。 | **Track Row = Y₁**。灯中心达到这一行就进入 `NEAR`。 |
| 近处通过 | 按希望的车身朝向和车灯间距摆车，量出灯到车身最近边缘的间距。选灯仍能稳定识别的位置，记录 `X₂、Y₂`，其中 `Y₂ > Y₁`。再镜像摆一次，记录另一侧。 | **Line Kp、Line Offset** 由下式计算。另在希望锁存绕灯方向的位置读一次 `Y`，设为 **Turn Row**。若锁存点恰好就是此次近处摆位，可直接用 `Y₂`。 |

固件要求 `25 ≤ Track Row < Turn Row ≤ 119`。在当前工作区版本里，灯已经进入近处后，即使先于 `Turn Row` 熄灭，也会沿上一帧的绕灯方向搜索。

### 用实际间距算动态中线

左右绕行的瞄准列分别为 `Mid X + 偏移` 和 `Mid X − 偏移`，默认转向约定下前者为左绕。先用近处摆位求 `d₂ = |X₂ − Mid X|`。如果左右镜像摆位的行号相近、偏移量也相近，可以取两侧偏移的平均值。两侧差异明显时，先复核车身朝向、相机安装和实际间距。

| 要算的量 | 公式或操作 |
|---|---|
| 动态中线偏移 | `偏移 = Line Kp × Y − Line Offset` |
| 两点求斜率 | 起始偏移取 0 时，`Line Kp = d₂ / (Y₂ − Y₁)` |
| 定入弯点 | `Line Offset = Line Kp × Y₁`。菜单中 `Line Kp` 步长为 0.05，先取可设置的斜率，再用该值算偏移常数并取最近可设值。 |

**算例**　假设正前方测得 `Mid X = 93`，入弯点 `Y₁ = 50`，近处通过时 `Y₂ = 100`。镜像摆位时灯中心分别在第 128 和 58 列，两侧偏移都是 35 像素。则 `Line Kp = 35 / (100 − 50) = 0.70`，`Line Offset = 0.70 × 50 = 35`。写入后，在第 50 行瞄准列为 93，到第 100 行左绕瞄准 128、右绕瞄准 58。以上数字为算例。

源码默认值为 `Mid X 93、Track Row 50、Turn Row 110、Line Kp 0.80、Line Offset 41`。记录并比较车上已有值，采用实测选定的一组后，在 **STOP → Params → Beacon → Save** 保存本页。

## 3. 两盏灯验证选边与灭灯重捕

1. 将第一盏灯放在前方，使它处于 `Y < Track Row`；第二盏放在更远的左侧。让两盏同时入镜，确认被选中的确是第一盏。下一轮把第二盏镜像摆在右侧。规划器只有在远处看见至少两个有效候选时，才会根据去往下一盏灯的路线主动选边。
2. 低速进入 **Run Beacon**，左右各跑一轮。记下开始侧移的距离、实测最近间距及近处的 `X / MID / ERR`。同一组参数应能使左右两侧都达到你摆位时选定的通过间距。参数修改回到 `STOP` 进行。
3. 当前工作区的原地搜索版本中，近处绕灯时熄灭第一盏，暂时让第二盏留在视野外。在相机持续出帧、搜索开启时，预期状态为 `SEARCH`，地轮目标前进速度为 0，车继续沿原绕灯方向转。第二盏进入视野并被判为有效的首帧即恢复 `TRACK` 或 `NEAR`。实车惯性和平衡修正仍可能带来少量地轮位移。

| 现场现象 | 优先检查 |
|---|---|
| 远处正对灯就往同一侧偏 | 重新核对车身中心线、相机朝向和 `Mid X`。 |
| 左右两边都绕得太晚 | 在希望开始绕灯的位置重新量 `Track Row`，再按新的 `Y₁` 重算中线参数。 |
| 近处 `ERR` 接近 0，但车身仍太贴灯 | 车已跟到给定瞄准列。把近处摆位改成期望间距，重测 `d₂` 并重算。 |
| 瞄准列移到了预期位置，`ERR` 却持续很大 | 比较目标与实际偏航角速度，检查 `Speed m/s` 和 `Yaw Max`。此时还要看车能否执行图像给出的转向。 |

## 4. 需要米制距离或多灯路线时，复核相机几何标定

单灯绕行的反馈直接使用像素误差。候选距离筛选和多灯路线排序还依赖 `pixel2world()`，它把**亮斑质心**投影到假定的平面，输出以米为单位的位置。工程沿用旧相机参数，信标没有单独的菜单几何标定入口。换镜头、改变相机安装高度或俯仰角后，应重新验证这条链路。

1. **先复核旧参数。** 固定车身参考原点和前进轴，在正前方、左右两侧各取近点与远点。实测每个灯相对车身的横向、前向距离，同时记录 Beacon 页的质心 `X、Y`。保持灯发光中心高度一致。用这些像素离线调用工程的 `pixel2world()`，把输出与卷尺记录逐点对照。
2. **需要重标时。** 用当前镜头和实际采集分辨率拍多姿态棋盘格，估计内参 `IM` 和畸变系数 `distCoeffs`。随后在实际安装姿态下，用已量好的平面点和对应像素求外参 `rvec、tvec`，并按所选车身原点核对 `OriginOffset`。标定平面高度要与实际使用的发光质心相符。实现里平面坐标加原点偏移后再乘 `0.001` 转为米，填写平移与偏移时要统一尺度。
3. **留点验收。** 另外摆几个未参与标定的点，检查左右符号、正前方横向偏差、近远距离误差和两盏灯的距离排序。相机几何参数改在固件源码中，编译烧录后再跑两侧。循迹菜单的 IPM 使用独立参数。
