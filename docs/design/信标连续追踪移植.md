# 信标连续追踪移植

2026-11-12，基于本地 `6725a8b`，参考 `feng0511/monotroch` 的 `bc24e89cac8d557327d03be9a24e940b9714adf7`。本次不实现距离减速、到点停车和已访问记录，也不更换现有直立PID、IMU或电机协议。

## 运行链路

CPU1每个有效采集帧执行识别和三目标局部排序，再执行 `beacon_follow_update()`；CPU0接收只读快照，沿当前方向PD、航向积分、Yaw两环、Roll优先混控执行。状态不再由两核共享可写的旧 `Turn_info`。来源函数原文及哈希在 `docs/reference/monotroch-follow/`。

- `TRACK`：cy低于Track Row，追固定Mid X。
- `NEAR`：cy达到Track Row，按接近方向使用 `Mid X ± (Line Kp×cy−Line Offset)`；动态中线限制在0..187。cy达到Turn Row后锁存近处转向。
- `SEARCH`：近处转向锁存后丢标立即搜索；否则本次Run已经看见过有效目标、且连续丢标达到Search Frames后，按上次目标左右位置选择搜索方向。搜索偏差为±Search Err。
- `HOLD`：未见过目标、等待搜索条件、搜索禁用或配置无效时不生成搜索指令。

重新识别后回到TRACK/NEAR。开始/结束Run、切换Beacon Mode、摄像头重启会清除历史；预览期间可以显示动态中线，但不能启动搜索，也不能把预览历史带入一次新Run。

原程序的 `error=cx-dynamic_mid` 在发布给当前Run时只反号一次，随后使用现有 `STEER_DIR`。所有近处偏差与搜索指令仍受方向滤波、像素限幅、Beacon Yaw Max、Yaw角速度限制、飞轮斜坡及Roll优先权限约束。Search Err默认60像素，但原有加权方向限幅等效约43.48像素，增加到更大不代表有更大最终转向输出。

## 与原程序的适配区别

1. 搜索时识别 `valid` 仍为0、目标X/Y为0，以单独的 `searching/steer_valid` 表示可搜索，绝不输出历史坐标作为新目标。
2. CPU0只接受本次Run已经应用、来源模式匹配、帧未过期的搜索快照。没有采集帧不更新搜索计数，已有失帧检查仍退出Run。
3. 连续丢标600ms仍结束Run并保持Balance；搜索不会重置丢标计时，也不允许无限盲转。50FPS下普通20帧等待约400ms，100FPS下约200ms，实际以处理帧率为准。
4. 未进入搜索时，丢标速度目标为0；搜索时取Run Lost速度，并同时受Beacon Speed和Run Straight上限限制。Lost=0可转向搜索但不主动前进。速度斜坡与物理惯性仍存在。
5. 不移植旧控制器的PID、转弯时直接改Roll/Pitch零点的旧系数，保留当前Lean与平衡控制。目标重选仍是局部图像规划，没有引入持久信标ID或访问历史。

## 菜单和验证

Params → Beacon新增Track Row=50、Turn Row=110、Line Kp=0.8、Line Offset=41、Search Err=60、Search Frames=20，均为停车修改并随本页Save保存。Track Row必须小于Turn Row；Search Err=0关闭丢标搜索。默认值集中于 `code/config.h`，旧Flash中没有这些名称时自动使用默认值，无需擦除已保存的直立参数。

Beacon页显示X/Y、MID、ERR、TURN、MISS和TRACK/NEAR/SEARCH/HOLD。Image的BIN+L中，红色短线是当前选中目标，绿色整条竖线是动态追踪中线；进入NEAR后不再要求红线始终对着画面中央。无有效目标时没有红色目标标记。

先停车检查单目标识别，再以Speed=0、Lost=0验证左右转向，最后低速检查近处中线移动、转向锁存和重捕获。Run Beacon仍为3秒内双次确认；运行时确认一次结束追踪并保持Balance，再确认一次完全停机，返回键仅退菜单。
