# Motor编码器极性菜单（2026-11-09）

本次在已有Roll增量PI修改基础上加入左右飞轮编码器方向的运行参数。只修改本地代码，没有提交、上传或烧录。

## 操作

1. 停止Balance、单轴测试和Jog点动，进入`Params → Motor`。
2. `Enc A`对应飞轮通道A的编码器极性，`Enc B`对应B；分别选择`+1`或`-1`。A/B以各自Jog实际驱动的电机为准，不假定接线必然与物理左右一致。
3. 修改后立即生效；本页`Save`保存这两项及其他Motor页参数。看到`Motor PAGE SAVED`后，正常复位会恢复保存值。
4. 每路分别执行`Jog A/B Fwd`、停止等待接近停转、再执行`Jog A/B Rev`。底部`AIRBORNE JOG ... CMD`是本地PWM指令，`RPM A... B...`是归一化反馈。稳定转动后，同通道CMD与RPM应同号。若两方向都反号，仅翻转该路Enc项。
5. 正在点动时再次确认Jog动作会停止。先停止再修改Enc，不能边运行边翻转反馈。

`Dir A/B`控制电机输出坐标，`Enc A/B`独立修正编码器反馈，不改变PWM方向。RPM为0不能靠翻转极性解决；若点动A而只有B转速变化，应检查通道对应关系。

## 实现和兼容

- 参数键：`enc_dir_a`、`enc_dir_b`，整数，只允许±1，菜单步长固定为2。
- 默认来源：`ENC_DIR_A/B_DEFAULT`引用`config.h`中的`FLY_ENCODER_POLARITY_A/B`，当前均为+1；Flash保存值优先。
- 换算：`本地反馈RPM = 原始RPM × enc_dir_a/b × MOTOR_DIR_A/B`。
- 文本和二进制接收均保留原始RPM；GetSpeed读取时统一换算，修改后不需要等待新反馈帧。-32768取反经宽位计算及饱和处理。
- 旧Flash按名称加载，不依赖param_t内存布局。旧记录缺少两项时保留各自默认值，其他PID、零点、网络配置不重置，不自动擦写Flash。
- Motor页原有保存机制自动包含新增两项；保存其他页继续保留已存的Enc A/B。
- 菜单在Balance、单轴测试或Jog运行期间禁止修改Motor参数；协议将Enc A/B识别为Motor参数，禁止运行中远程写入，并校验±1。
- 参数数目由78增至80，Motor页由9项增至11项，仍在页面保存数组20项及Flash单页容量以内。
- 仓库内上位机profile加入两项的名称与说明；没有替换桌面上位机程序。
