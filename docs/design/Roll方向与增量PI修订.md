# Roll方向与增量PI修订（2026-11-09）

本次以本地462b924为基线，仅修改TC264主控与配套参数说明。未烧录驱动板、未烧录主控、未进行实车方向验证、未上传。

## 控制关系

```text
Speed：20ms，位置式PID
  r = 已归一化RPM_A - 已归一化RPM_B
  offset = PID_speed(r)
  Roll目标 = Roll零点 + clip(压弯偏移 + offset, -10°, +10°)

Angle：1ms，位置式PID
  angle_out = PID_angle(实际Roll - Roll目标)
  目标角速度 = -angle_out

Rate：1ms，增量式PI
  e = 陷波后的实际Roll角速度 + angle_out
  Δu = Kp×(e[k]-e[k-1]) + Ki×e[k]
  内部u[k] = 内部u[k-1]+Δu（积分触及输出边界时限制新增积分）
  PWM = clip(内部u[k], -10000, +10000)

纯Roll混控：A=-u，B=+u；Balance还叠加原有Yaw分量。
```

PI独立记录未限幅的P项与有界的I输出分量，不把截断后的PWM当作完整内部历史。否则KI=0也可能在P饱和后留下偏置。积分只在有输出余量或帮助退出饱和时增加，其贡献另限于PWM范围。KI=0时清除I分量，P饱和后误差回零，PWM也回零；KI非零时误差归零仍可能保留原有积分输出。Stop、故障退出、单轴测试启动/退出、Balance重启均经现有reset路径清除输出及历史。

初次软件迭代保留Rate KP=20、KI=0；随后用户提供实车菜单照片并要求固化，当前默认值为Rate KP=45、KI=0.05，其余Roll参数见[实车参数记录](Roll实车参数20261109.md)。KI按每拍计算，在1ms周期下，每秒约执行1000次。KI=0表示不新增积分。旧Rate KD固定归零且非零写入被拒绝；保留参数键以兼容旧协议和Flash，其余已保存参数照常加载。旧KD=8不再参与运算。菜单移除了Roll Rate Kd，其他轴的KD仍保留。

Angle和Speed继续使用位置式PID。Angle保留原有5ms参考增益到1ms运行周期的换算。IMU融合、两处陷波、引脚、WiFi、机械零点和其他轴控制没有在本轮修改。

## 输出方向与编码器方向

在`Params → Motor → Enc A / Enc B`修改左右编码器极性，参数名为`enc_dir_a/b`，各自只能为+1或-1；Motor页Save保存到Flash。`config.h`中的`FLY_ENCODER_POLARITY_A/B`现在仅提供无保存记录时的默认值：

- 驱动端正PWM对应正的原始RPM：该路设+1。
- 驱动端正PWM对应负的原始RPM：该路设-1。

主控换算：`本地反馈RPM = 原始RPM × 编码器极性 × MOTOR_DIR`。输出仍为`驱动PWM = 本地PWM × MOTOR_DIR`。因此可独立修正磁编码器符号，不必为此反转已确认的电机输出方向。文本和二进制回传使用同一换算，-32768取反时进行宽位计算及饱和，避免溢出再次变负。

两路编码器极性默认均为+1，旧Flash缺少新参数时不清空其他参数；已保存的Enc A/B优先于编译默认值。接收缓存保留原始RPM，读取时按当前方向换算，因此停车修改后屏幕立即变化，不必等待新回传或重新编译。默认+1并非已确认当前驱动板内的标定结果。CYT参考驱动UART回传原始编码器方向，而内部FOC使用rotation_direction；实际标定值不能从TC264源码推知。

Speed改为“零点加回收偏移”，前提是上述反馈已正确归一化，且正u产生负Roll角加速度。对直立附近模型`θ''=aθ-bu`、`r'=-cu`（a,b,c>0），正r对应正目标θ，重力平衡所需正u使r减小。此符号模型用于审查，不能当作本车动力学辨识或稳定性保证。不可同时再把A-B改成B-A，否则会双重翻转。

## 诊断与菜单

Balance与Roll单轴Speed测试共用`roll_target_update()`，目标均限制在零点±10°，遥测`roll_target`更新为实际使用的目标，消除原先单轴测试目标显示过时及缺少相同限幅的问题。

Roll菜单按参数名判断所属环，不再依赖固定行号。Rate KP/KI和Rate Notch属于Rate，Angle三项属于Angle，Speed三项属于Speed。

## 验收边界与上板顺序

主机回归执行实际C函数，覆盖增量PI、限幅/反向/复位、Flash兼容、三环符号和目标、菜单归属，以及左右输出/反馈方向组合和两种UART转速格式。可用GCC运行；设置`ONEWHEEL_HOST_TCC`可在本机原生编译器无法写临时文件时使用TCC内存运行。TCC专用数学头仅用于主机测试，调用系统CRT数学函数，不进入固件构建。

ADS编译证据在`.ads/build/latest.json`，新HEX应核对哈希后复制至工程Debug。编译通过不代表已经烧录或实车验证。

上板先核对两路各自正/负PWM与回读符号，再验证Rate阻碍转动、Angle推动回正，最后加入Speed观察转速回收。不能用固定车身时的瞬时制动，代替放开Roll轴后的回收方向验收。参数先保留记录，PI的新积分增益需重新试调。
