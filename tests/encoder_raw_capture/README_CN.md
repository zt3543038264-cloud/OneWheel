# 编码器 raw / delta 独立采集 v1.1

## v1.1 修正

v1 把完全相同的订阅重复宣告也当成错误。已核对故障日志，最后两次 SUB 的字段及顺序
完全一致；基线固件每 1000 ms 会主动发送当前 SUB / RATE / STREAM 信息。
v1.1 允许这些内容完全一致的重复元信息，不把它们当成数据样本，也不重置数据时间基线。
字段改变或重排、周期改变、关闭遥测、时间回退和非停车状态仍会中止。
只有元信息而没有新数据仍会超时，不会把持续宣告误当成采集成功。

## 为什么单独提供这一小包

原 `main_wheel_three_loops_v1.zip` 的 `speed_loop.py capture` 没有订阅
`wheel_encoder_raw`、`wheel_encoder_delta`，也没有自定义通道选项。本包专门补这一次
静止 / 手动缓慢转轮的原始编码器记录。不需要先知道原上位机的 profile 名称。

独立解压本包，不覆盖原工程、原上位机或原三环工具。Python 3.9 或更高版本，只有标准库，
不需要 pip、安装驱动、重新编译或烧录固件。

## 操作前的必要条件

1. 板端已实际 Stop，退出 PWM 预览、飞轮开环等测试。
2. 按现有硬件操作规范可靠隔离电机动力，保留控制板和编码器通信所需供电。
   不要把屏幕上 PWM=0 当作隔离。若不能可靠隔离，先不要运行本实验。
3. 保持可靠支撑，手动转轮也要远离夹点；无人操作 Start、模式或菜单。
4. 关闭原上位机 UDP 接收及其他命令发送器，避免占用 8081 或改变订阅。
   不要为了抓数据启动电机。
5. 电脑与板子网络仍使用原来能通信的设置。当前目标板 IP 已填为 `192.168.0.119`，
   板端 UDP 5001，电脑接收 UDP 8081。IP 不是电脑地址。

## Windows 最简单的运行方法

解压后进入 `encoder_raw_capture` 文件夹，双击 `START_CAPTURE_WINDOWS.cmd`。
只有实际完成上述安全检查后才输入 `YES` 回车。

看到 `CAPTURING` 才开始计时：先让轮子静止约 3 秒，随后在安全隔离的条件下缓慢手动
转动一小段，停下，再反方向缓慢转动一小段。无需精确一圈，不要碰 Start。
约 20 秒后自动结束。窗口会显示日志完整路径。

如果不使用双击入口，在该文件夹的 PowerShell 中运行：

```text
python encoder_raw_capture.py --device-ip 192.168.0.119 --seconds 20 --confirm-stopped-isolated
```

如果原三环工具用的是 `py -3`，把开头的 `python` 换成 `py -3`。
`--confirm-stopped-isolated` 表示你已经完成上述检查；脚本本身不会停止或隔离电机。
不带此选项时，脚本直接退出，连网络 socket 都不会打开。

## 把哪个文件发回来

把本文件夹中新生成的 `encoder_raw_日期_时间.jsonl` 原文件发回。
每次自动取新文件名，不覆盖旧记录。即使报错也保留部分日志，可连同完整错误文字一起发回。
不需要逐行复制，也不要只发曲线截图。

窗口约每半秒显示一次 raw、delta、seq、dt_ms、valid、speed_cps；实际按约 20 ms 遥测记录。
日志还包括编码器错误数 / 符号、反馈有效性 / 年龄、位置计数 / 有效性，以及板端停止状态字段。

## 脚本做了什么

唯一允许发送的四条指令是：

1. `GET?`：记录原有遥测订阅、周期和开关。
2. `SUB ...`：选择本包固定的 21 个字段，其中包含 raw / delta。
3. `RATE 20`：请求 20 ms 遥测周期。
4. `STREAM 1`：开启遥测发送。

这些只是遥测配置变更。没有 Start、Stop、模式切换、PID / 参数写入、Flash 保存、
方向、零点、PWM 或 DTRACE 指令。`STREAM` 不是电机启停。

日志保留 `ORIGINAL_TELEMETRY`。退出后不自动恢复旧订阅，raw / delta 订阅和 20 ms 周期
可能仍然生效。之后重新用原上位机记录前，需要在原上位机里重新选择其波形订阅。
本包没有改动或覆盖原上位机的配置文件。

## 如何理解数值

- `wheel_encoder_raw`：基线源码中的 16 位硬件计数器读数，范围 0～65535，跨 65536 回绕；
  不是限定为 0～4095 的一圈绝对角度。用于判断传感器是否随手动转轮变化。
- `wheel_encoder_delta`：固件发布的最近一个采样窗口增量，不是整段试验累计转角。
- `seq / dt_ms / valid / errors`：帮助区分新采样、重复窗口、无效数据和通信 / 编码器问题。
- 读数跨过编码器周界时可能回绕，不要把单次 raw 大跳变直接当成故障。
- 遥测可能漏掉采样窗口，不能简单对所有重复显示的 delta 求和当总转数。
- Stop 下速度环反馈可能与原始编码器更新不同步；不要只凭 speed_cps 的正负或为零
  判断电机方向、速度环正负反馈或传感器故障。

## 遇到问题

- 端口占用：关闭原上位机 UDP 接收，勿随意换 8081。
- 超时：检查 IP、现有网络、板子目的电脑地址、5001 / 8081 和本机防火墙状态。
  本包不会改网络或防火墙，也不会自动重发。不要用 Start 来测试通信。
- 订阅不匹配 / 未知字段：保存日志，核对固件版本，不手工猜字段顺序。
- `Stopped-status check failed`：程序中止采集，但不发送 Stop。继续保持动力隔离，
  按已有本地安全流程检查状态。单纯退出本程序不会停止电机。
- Ctrl+C：中止并保留部分日志，不发送电机控制或回滚命令。

## 验证范围

字段名取自已交付 v1 包中的 `protocol_fields.json`，其源码基线是 OneWheel `new`
分支 `dcce786` 加当时工作区变更。v1.1 重新核对了该基线的遥测宣告和编码器计数源码，
但用户当前板子实际烧录的固件版本仍未确认。

可以离线运行：

```text
python -m unittest discover -s tests -v
```

测试只使用合成数据和本机 `127.0.0.1` 模拟板，不接触真实板子。
详情见 `VALIDATION.md`。Windows 双击入口未在真实 Windows 系统中实测；
Python 主程序在当前 Linux 环境通过本机 UDP 测试。未连接真实硬件，软件状态检查不等于
硬件安全联锁，也不证明实车控制稳定。
